# Adopting the skeleton: what AFTERSHOCK needed

AFTERSHOCK was built second, from the same skeleton, by the `aftershock` Kiro spec (27 ledger sessions). It changed **zero files under
`skeleton/`** (checked against each session's `files_changed` in [`evidence/kiro/sessions.jsonl`](../evidence/kiro/sessions.jsonl)).
Later UI polish touched skeleton CSS and markup for both apps (recorded in `.kiro/specs/ui-polish/design.md`, "Skeleton changes").

## The five things an app supplies
1. **Model**: `apps/aftershock/src/model.ts` (`materialize`), the sector grid state folded from ops.
2. **Ops**: one `*.op.ts` per op in `apps/aftershock/src/ops/`, each declaring `merge` (a named rule) and `intent`.
   `registry.gen.ts` is generated by the `op-scaffold` hook.
3. **Seed script**: `src/seed.ts` and the lake-scene equivalent in `src/scene.ts`.
4. **Views**: `src/views/` (sector card, report form, twins, shuffle section).
5. **Config**: `apps/aftershock/app.config.ts` exports `name`, `defs`, `materialize`, `describeConflicts`, `twinCount`, `seedOps`, `goldens`, `members`.

## Files outside `apps/aftershock/` the spec had to touch
- `kit/props/intents.json` and `kit/props/manifest.test.ts`: register the app's ops in the intent manifest (the kit gates by manifest).
- `vitest.config.ts`, `playwright.config.ts`, `pnpm-lock.yaml`: add the app's test projects and workspace.
- `e2e/aftershock-offline.spec.ts`, `evidence/aftershock/`, `evidence/convergence/full-2026-11-21-aftershock.json`: the app's offline test and its recorded runs.
- `site/index.html` and `.gitignore`: landing page link and ignore rules (task 24).
- `.kiro/specs/aftershock/`: Kiro's own spec files.

Steps, in order: copy the app folder shape from `apps/basecamp`, write ops, run `pnpm props`, add the app to the manifest, add views,
`pnpm --filter @limbo/aftershock dev`.
