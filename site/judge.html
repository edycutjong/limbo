LIMBO, for judges

v0.1.0 · landing page

When the connection dies, your app keeps working. When it returns, an item deleted while it was edited comes back as a ghost twin, and a lost claim is shown to its owner.

The judge path

No setup, no keys, no cloning.

  1. Open BASECAMP in its two-replica view. No install, no login, no credits. Two cards appear: REPLICA A (Sari) and REPLICA B (Budi), joined by an in-page link that is labelled as simulated.
  2. Press Cut link. Both cards fog over and count their waiting edits.
  3. Press Play the lake scene. Sari ticks the tent while Budi deletes it, and both claim the last stove.
  4. Press Restore link. The tent returns as a ghost twin; the stove goes to exactly one claimant on both replicas.
  5. Tap Keep on the twin and OK on the lost claim. The fog lifts and the FIXED stamp appears: both replicas hold the same list.
  6. Now your own edit, not the scene: type an item into Add an item on REPLICA A (it appears on B), press Cut link, tick it on A and delete it on B (⋯ then Delete), press Restore link. It comes back as a twin on both cards (rule: resurrect); Keep settles it.
  7. Open AFTERSHOCK (a second, different app on the same skeleton) and run the same cut, Play the survey scene, restore. Resolve the lost note by tapping either Keep … note button on the twin card.
  8. Then press Run shuffle test in either page's shuffle section: it replays the on-screen ops in random causal orders in your browser (the same ops replayed, not the 10,000-ordering run).

Where Kiro did the work

  • .kiro/specs/: requirements, design and tasks for each feature, authored by Kiro sessions from an orchestrator brief. Start with .kiro/specs/basecamp/ or coverage-full/.
  • .kiro/steering/: the rules Kiro was held to: local-first.md (no wall clock, commute or declare the merge) and testing.md (properties first).
  • .kiro/hooks/ and .kiro/agents/: the hooks that ran the convergence properties after each task and blocked the agent from stopping while one failed.
  • .kiro/hooks/stop-gate.json: blocked Kiro from finishing 2 times. Once unplanned: in merge-kit task 9.5 the shared property suite ran the new item.move op without its own payload generator, and Kiro wired it in (commit 651730d). Once on a wall-clock fault seeded on purpose (commit cca30a0); that is the session the video replays.
  • evidence/kiro/sessions.jsonl: one row per Kiro session (spec, task, credits, hooks fired, outcome). Hand edits are logged as claude-direct rows. hooks.jsonl is written only by the hook scripts.

Reproduce it

  • git clone https://github.com/edycutjong/limbo && cd limbo && pnpm install: the real product, locally
  • pnpm --filter @limbo/basecamp dev: BASECAMP on http://localhost:5174 (AFTERSHOCK: pnpm --filter @limbo/aftershock dev)
  • pnpm test:coverage: unit, component and property tests with the 100% coverage gate
  • pnpm e2e:ci: two browser contexts, a real partition, offline shell
  • pnpm props:full: the full 10,000-ordering tier (about 22 minutes)
  • node kit/scripts/readme-tally.mjs: recomputes every Kiro number above from evidence/kiro/

CI / deterministic replay. The in-page "Run shuffle test" button replays the on-screen ops in random causal orders inside your browser and prints the count it actually ran. It is a deterministic replay of the same ops, not the full-tier run.

Honest limits

  • The live apps sync two replicas through an in-page link that is labelled as simulated. There is no hosted cross-device relay; the two-browser-context partition test uses a dev-only relay that ships in no production build.
  • No CRDT can stop two offline users from both claiming the last tent. Offline claims are provisional; on reconnect the op's declared rule picks one claimant deterministically and the other user sees a twin ghost.
  • The pre-registered A/B pilot (20 op-writing runs with and without the kit) showed no measurable effect: held-out failures 0 of 10 in both arms (95% CI 0 to 28%, Fisher p = 1). We claim nothing about the kit improving correctness. It is published as run (evidence/kiro/ab/).
  • AFTERSHOCK uses demonstration data; no field use is claimed. The Kiro IDE features (Spec Correctness, Agent Hooks panel) were not used: every Kiro session ran through the Kiro CLI, dispatched by an outside orchestrator. Edits made outside Kiro are logged too: 17 claude-direct ledger rows, and 9 of 124 product commits (listed in evidence/kiro/share.json).
